# Y7SK — Architecture & Design

**Status:** Accepted · **Date:** 2026-05-30
**Runtime (verified current):** Electron 42.x · electron-vite 5.x · electron-builder 26.x · Vite 7 · React 19 · Zustand · TypeScript · Node 22.

Y7SK is a lightweight cross-platform desktop client that wraps **soundcloud.com** in a native child view, with a fully custom frameless React title bar, OS media integration, persistent login, system tray, and local settings. No backend, CI, telemetry, or online services. Local use only.

Security profile fixed on **every** webContents: `contextIsolation:true`, `sandbox:true`, `nodeIntegration:false`.

---

## 1. Window & rendering model

One `BrowserWindow` host + one child `WebContentsView` for SoundCloud. `BrowserWindow extends BaseWindow`, so it provides both its own renderer (the React title-bar shell, via `loadFile`) and the inherited `contentView` for the SoundCloud view.

- **Layering:** native child views composite *above* host HTML. Title bar = reserved 40px strip; SoundCloud view inset below via `setBounds({x:0,y:40,width,height:height-40})` using `getContentBounds()` (client area).
- **Settings panel:** HTML in the host renderer, *under* the native view. Open → `scView.setVisible(false)` reveals it; `setVisible(true)` restores. Audio + state preserved.
- **`backgroundThrottling:false`** on the SoundCloud view — keeps audio/timers/metadata-observer responsive while hidden or minimized-to-tray.
- **Resize:** `setAutoResize` removed; set bounds once after `addChildView`, then on every `win.on('resize')`.
- **Lifecycle:** clean up the view in `win.on('close')` (not `'closed'`) with `isDestroyed()` guard to avoid the documented leak. Create view only after `app.whenReady()`.
- **Corners:** SoundCloud view stays opaque/rectangular; round only the outer window (`roundedCorners`). Known cosmetic divergence: ignored on Linux (square corners).

## 2. Frameless title bar

`frame:false` — not `titleBarStyle:'hidden'` (keeps macOS traffic lights) nor `titleBarOverlay` (re-adds native Win/Linux buttons). Only `frame:false` yields identical custom controls on all three OSes.

- `app-region:drag` on the bar (+ `-webkit-app-region` alias), `app-region:no-drag` on every interactive child, `user-select:none`.
- Edge-resize works while `resizable:true`. Linux: `hasShadow:false`.
- Maximize icon reactive via main `'maximize'`/`'unmaximize'` events → renderer.
- macOS double-click: read `systemPreferences.getUserDefault('AppleActionOnDoubleClick','string')`, handle `Maximize`/`Minimize`/`None`/`null`.

## 3. Process & security model

Two separate preloads:

| Preload | Attached to | Role |
|---|---|---|
| `preload/index.ts` | host BrowserWindow | trusted — exposes `window.y7sk` |
| `preload/scbridge.ts` | SoundCloud view | read-only MediaSession observer; `ipcRenderer.send` only; exposes nothing to the page |

`window.y7sk`: `minimize, toggleMaximize, close, isMaximized, onMaximized, titlebarDblClick, showSoundCloud, getSettings, setSetting, onSettings, onTrack`.

Channels namespaced (`win:* / view:* / settings:* / track:changed`); state-changes via `invoke/handle`, fire-and-forget via `send/on`. Every payload validated in main (settings key allow-list, boolean coercion). Host shell ships CSP `<meta>`; `webSecurity:true`.

## 4. Session, auth & navigation

- `partition:'persist:soundcloud'` → persistent isolated session; login persists with zero extra code.
- `setWindowOpenHandler`: deny non-http(s); OAuth providers (Google/Apple/Facebook) → `shell.openExternal` + deny (Google blocks embedded UAs); SoundCloud-host popups → allow via `createWindow` with explicitly-built `webPreferences` on the same partition; other sites → openExternal + deny.
- `will-navigate` keeps top-level nav inside `*.soundcloud.com` (incl. auth subdomains).
- Default UA; per-session Chrome UA override only if "unsupported browser" appears.

## 5. Media & OS integration

- No `globalShortcut`. Chromium `HardwareMediaKeyHandling` (default-ON) routes keys to SoundCloud's MediaSession, which drives Windows SMTC / Linux MPRIS / macOS Now Playing automatically. Never disable that feature. SoundCloud view = sole audio source.
- Optional Windows thumbar (best-effort, dispatch MediaSession actions via `executeJavaScript`).
- Notifications (track + playback): `scbridge` observes `metadata` + `playbackState`, sends via IPC; main raises `Notification` (gated by `isSupported()`).

## 6. Tray & lifecycle

- Tray always created: menu **Open Y7SK · Show Window · Reload · Quit**, double-click → restore.
- Real-quit via `app.isQuitting` flag; close/minimize→hide only when not quitting.
- `requestSingleInstanceLock`; second instance focuses existing window.

## 7. Settings (electron-store)

Renderer never touches store; all via `settings:get/set`, main broadcasts `settings:changed`. Five booleans:

| Setting | Applied via | Timing |
|---|---|---|
| launchOnStartup | `setLoginItemSettings` (Win/mac); Linux autostart `.desktop` (uses `$APPIMAGE`), removed on disable | immediate |
| alwaysOnTop | `win.setAlwaysOnTop` | live |
| hardwareAccel | `if(stored===false) app.disableHardwareAcceleration()` before ready | startup-only (UI: restart required) |
| startMinimized | `show:false` + `ready-to-show`→minimize, or straight to tray | launch |
| minimizeToTray | gates close/minimize→hide (tray always exists) | live |

## 8. Window-state persistence

`size/position/maximized` to electron-store (debounced), restored with on-screen-bounds sanity check.

## 9. Build tooling & structure

electron-vite 5; `sandbox:true` ⇒ both preloads bundled CJS; main is ESM (`import.meta.dirname`). Dev: `electron-vite dev --watch`; dev/prod gate on `!app.isPackaged && ELECTRON_RENDERER_URL`. tsconfig project references (node + web). `electron-store` is the only runtime `dependency`; React/Zustand/etc. are `devDependencies` (bundled).

```
src/main/ {index, window, soundcloud-view, tray, media, settings, window-state}.ts
          ipc/{index,window,settings,view}.ts  util/{paths,autostart-linux}.ts
src/preload/ {index.ts, scbridge.ts}
src/renderer/ index.html  src/{main.tsx,App.tsx,components/*,store/*,hooks/*,styles/*}
src/shared/ {ipc-channels,settings,types}.ts
build/ (icons)  resources/tray/ (runtime PNGs)
```

## 10. Packaging

`electron-builder.yml`: `appId:com.y7sk.app`, `productName:Y7SK`, `asar:true`, `files:[out/**,package.json]`, `main:./out/main/index.js`. Win nsis+portable, Linux AppImage+deb, mac dmg. Icons from `build/`. Tray icon is a runtime asset.

## 12. Runtime risks to smoke-test (not assume)

MediaSession regressions (pin Electron, verify per-OS keys/SMTC/MPRIS/Now-Playing/notifications); OAuth handoff; default-UA acceptance; Wayland `maximize`; Linux autostart across distros; WebContentsView leak.
